# ADR-012 — Pure constrained routing and current snapshot responses

Accepted 2026-10-12 for Phase 3.

**Problem:** Route results must prove hard accessibility limits from current observations, remain optimal under their declared cost model, and correspond to a consistent database revision even when administrators edit infrastructure during calculation.

**Decision:** A standard-library-only routing package consumes frozen graph/node/physical-edge/dependency/profile values. PostgreSQL/PostGIS remains authoritative for measured distance and geometry. The adapter exports 15-digit coordinates, retains exact endpoints, and loads rows and metadata within one read-only repeatable-read transaction. Only active physical edges participate; inactive nodes and mapped infrastructure still prevent traversal. A same-snapshot aggregate checks geometry size before geometry transfer/JSON decoding: at most 10,000 graph rows per collection, 1,000 points per physical edge, 100,000 total active-edge points and 100,000 associations. Projections omit unneeded raw geometry, duplicate JSON and provenance columns.

The engine validates finite values, endpoint identities/geometry, unique directed physical identities and the WGS84 ECEF chord lower bound. It excludes prohibited edges before optimization. Missing or noncurrent measurements never prove a hard limit; permissive uncertainty applies only when all requested hard constraints can still be established. Cost is the nonnegative `walking-effort-v1` metre-equivalent formula; actual distance and speed-based estimated duration remain separate. Dijkstra and A* relax strictly lower costs, retain predecessor arcs for parallel paths, use stable heap tie ordering and handle known same-node requests as zero-edge Points.

Yen enumerates loopless candidates on the same filtered multigraph, including diversity-rejected candidates in its search partitions. It returns at most two additional paths, each within 1.5× primary cost and at most 80% shared physical distance with every accepted route. At most 20 additional candidates are popped. All searches share a default 100,000-expansion/two-second budget. Primary-budget exhaustion returns 503; exhaustion only during alternatives retains the proven primary and explicitly marks the alternative search incomplete. Reaching the requested number is complete for that requested limit; it does not claim all possible paths were enumerated.

Observation-expiry maintenance commits before snapshot loading. Search holds no graph mutation lock. Final validation reuses the shared expiry/mutation lock and checks graph/policy/cost versions and freshness deadline; a mismatch rebuilds once, and a second mismatch returns 409 `GRAPH_CHANGED_RETRY`. A route is current at its returned validation instant. There is no route-result cache. The frontend polls the graph-version endpoint every ten seconds while a result is shown, checks on focus/visibility return, and invalidates on known version changes, failed confirmation, offline events, changed inputs or observation expiry. Event-driven invalidation remains Phase 4.

The public POST accepts an explicit complete profile and performs no account/preference/route-history mutation. It needs no login/CSRF; this is the documented read-only exception to state-changing endpoints. An optional authenticated identity or keyed client IP receives the existing durable 60/minute quota. The optional-auth transaction commits and releases its connection before independent quota/snapshot sessions, preventing nested connection-pool starvation. RFC 8785 serialization uses the separately hash-locked `rfc8785==0.1.4` package; sorted/deduplicated surfaces and equivalent numeric representations have one SHA-256 fingerprint.

Route geometry and signed reverse slopes follow directional arcs. Per-arc instructions reconcile with actual totals. Verification coverage is length-weighted, uncertainty remains per route, and global warnings identify synthetic data and estimated duration. No-route includes physical-edge exclusion counts and distinguishes structural disconnection from constraints without silently relaxing a profile.

**Alternatives:** Keeping the graph lock throughout search is consistent but blocks administrative updates for the entire calculation. Reading separate tables under ordinary read committed can mix revisions. A route cache would require complete profile/version/freshness keys and adds no demonstrated benefit yet. Handwritten ad hoc profile JSON normalization risks inconsistent identities; the small canonicalization dependency makes the stated fingerprint contract explicit. Huge penalties for hard constraints could still select forbidden paths and are rejected.

**Validation:** Independent exhaustive generated-graph oracle comparisons, constraint/unknown/closure/budget and heuristic invariants, real-PostGIS snapshot/concurrent-edit/expiry tests, live API/browser geometry and totals, and a deterministic 2,000-node/5,000-pathway pure-engine benchmark. Actual counts, outcomes and remaining limits belong in [Phase 3 evidence](../PHASE3_TEST_EVIDENCE.md).
