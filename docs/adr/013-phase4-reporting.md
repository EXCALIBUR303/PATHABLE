# ADR-013 — Reviewed restrictions, private evidence and durable live updates

Accepted for Phase 4, authorized and verified 2026-10-13. See [executed evidence](../PHASE4_TEST_EVIDENCE.md).

Report content is immutable after submission. Creation stores submitted/pending history without affecting graph eligibility. Administrator verification creates source-specific physical-edge restrictions; resolution releases only that report's rows. The shared graph-state lock, revision/event service and expiry mechanism remain authoritative. Requests claim actor/operation/UUID idempotency within the domain transaction; a deferred DB guard rejects incomplete claims. Expected versions, history, audit, restrictions, graph revision and recorded response commit or roll back together. A read-only replay remains role/owner authorized.

The migration adds composite same-campus references and deferred report/restriction consistency guards. Existing campuses receive a new reset revision when reporting semantics are introduced; existing data is retained. History remains append-only under the application DB role.

JPEG/PNG uploads are parsed only after authentication/resource authorization. Actual request bytes are bounded independently of Content-Length; multipart cardinality, file bytes, dimensions, format, animation, report slots and user storage are bounded. Processing reserves the maximum normalized size under user/report locks, then releases the DB connection while a separate Pillow process decodes. The worker has a 512 MiB address-space limit, four-second CPU limit, six-second parent timeout and bounded output; at most two decoder processes run per API process. A new image strips source metadata. Private UUID filenames, mode-600 files, atomic rename and processing/ready/rejected states protect partial work. Verified evidence cannot be removed through the pending-owner endpoint. Explicit owner-role maintenance expires replay/lease records and removes old interrupted/orphan uploads while preserving ready content.

SSE reads committed per-campus graph events with one-second short transactions; cursors replay retained contiguous revisions or reset. Public frames omit report descriptions, identity and evidence. Changed-edge lists are capped at 200 IDs with an explicit truncation flag, keeping frames bounded; every newer campus version invalidates routes regardless of intersection. Database leases enforce three streams per identity and a global 200-stream admission cap; leases expire after 45 seconds if cleanup cannot run. The app role does not delete audit/event history; the owner maintenance command implements seven-day event retention.

The frontend uses fetch streaming rather than native EventSource so it can observe heartbeat comments, enforce the 45-second liveness deadline and explicitly carry Last-Event-ID on bounded reconnect attempts. This is a transport adjustment to the design's EventSource recommendation; it preserves the SSE wire protocol, durable replay and cookie-only identity. Automatic rerouting preserves the complete profile and uses cancellation/generation/version guards; results require explicit confirmation after live changes before guidance resumes.

Analytics count physical pathways and reports directly, with defined current-stock and [from,to) flow windows. Evidence and overlapping restriction joins cannot multiply these counts. Empty denominators and empty resolution means return null. Charts have text/table counterparts. Final acceptance passed: 303 backend tests, 38 component tests and 18 real full-stack browser tests; frozen installation/startup and saved cloud instructions are separately documented in the evidence.

An empty retained replay sends an immediate heartbeat comment so the same-origin proxy flushes the resumed connection. The client observes comments, treats 45 seconds without data as loss of currentness, cancels stalled reads and confirms the graph version before announcing reconnection. Mutations recheck the active role/auth version with a user share lock. Non-graph report changes use scoped ten-second queue/history/audit polling and thirty-second analytics refresh.
