# ADR-015: explicit HTTPS release operations and coordinated private backups

Status: accepted for Phase 7 local release preparation, 2026-10-13.

The development server and retained development DB are kept separate from a release Compose project. Pinned Python/Node/Nginx image digests build a native production UI and API. Verified Python wheels and npm integrity cache are fetched through the host first; Docker build steps run without network access. The context excludes private configuration, datasets, weights, uploads, development environments and test output. API/web run as configurable non-root users with read-only roots, bounded temporary filesystems and resource/process caps.

The release API gets only its restricted DB credential. Owner credentials are optional in Settings and required only when an owner URL is requested; explicit operator containers receive them for migrations, maintenance and administrator bootstrap. Migrations run as one controlled operation, with no replica startup DDL. The PostGIS image initializes its bootstrap database separately from the application DB; migrations or restore explicitly create the latter. DB health checks use TCP, which excludes the temporary initialization-only socket server.

Nginx serves same-origin HTTPS and compiled static assets, emits CSP/HSTS/frame/referrer/permission headers, bounds body size and disables stream buffering. The core still ignores forwarded IP headers. Anonymous abuse buckets therefore aggregate behind this single proxy; trusted client-IP propagation/admission is a future capacity/abuse decision, not implicitly enabled by adding Nginx. External tile providers remain unconfigured and outside the default CSP. TLS private keys and uploads are private host mounts, never static content.

Operator commands share a per-project file lock. Coordinated backup stops API/web writers, dumps the DB and copies immutable private evidence/model storage, writes a checksum manifest last and resumes exactly the previously running application services. External manual writers must also be quiesced. ML remains disabled; enabling a future worker requires adding it to this orchestration. Backups contain sensitive data and require encrypted off-host retention and access controls set by the operator.

Restore validates file membership/hashes and rejects symlinks/path escapes before mutation. It requires stopped services, empty private storage and a pristine application DB, creates a missing target from template0, restores transactionally, installs this target's current role credentials/grants and leaves services stopped for review. It never cleans or overwrites a populated application target. TLS/operator credentials are restored separately; rotation may invalidate old sessions. Checksums detect corruption, not authenticity: only trusted operator backups may be restored.

Validation uses explicitly synthetic, loopback-only fixtures with short-lived self-signed certificates. Python verifies the certificate chain/host/validity against the explicit fixture CA; the browser pins that certificate's public key. No public certificate provisioning, DNS, remote deployment or environment publication is implied. Remote CI and fresh-task restoration require independent evidence.
